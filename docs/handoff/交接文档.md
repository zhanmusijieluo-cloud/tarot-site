## 1. 项目是什么

mustar.vip —— 塔罗 + 专业占星网站（中文站，双语 zh/en）。

- 塔罗板块：韦特/雷诺曼抽牌、牌阵、AI 解读（已上线运营）
- 占星板块：本命/推运/行运/天象/法达/小限 + 合盘 16 种盘，全部对齐市面专业软件（测测/爱星盘/宫神星）口径
- 后端：Supabase（账号 Auth + 云端档案库 user_archives + 牌义库 card_meanings + 学习文章 learn_articles）

## 2. 技术栈与常用命令

Next.js 16.3.1 (App Router) + React 19 + TypeScript 5 + Tailwind CSS v4 + Three.js 0.185（3D盘）+ @supabase/supabase-js。

```bash
cd D:/网站/塔罗/tarot-site
npm run dev                # 本地预览 http://localhost:3000
npx tsc --noEmit           # 类型检查（每次改完必跑，要求 0 错误）

git push origin master     # 推送 → GitHub 自动触发 Vercel 部署（mustar.vip，约几分钟）
```

- 部署链路：`git push origin master` → GitHub `zhanmusijieluo-cloud/tarot-site` → Vercel 自动部署。**没有单独的部署命令，push 即上线。**
- 验收截图/DOM 断言脚本全部在 `scripts/`（下划线开头的是排查/验证脚本，如 `_syn_rows_test.mjs` 合盘清单行格式断言、`_fir_dual.mjs` 法达环断言、`_click_planets.mjs` 全16盘点击测试）。

## 4. 全站 UI/产品铁律（爸爸逐条拍板的，违反必返工）

**视觉**
- 中文站星座显示用汉字/手绘矢量，**禁用 Unicode 星座符号**；四元素色 火`#ff9c90`/土`#f0c470`/风`#84e89e`/水`#8cc0ff`。
- **行星符号保持 emoji 原样**，谁都不许乱动。
- 相位四色（单一表 `src/lib/astro/aspect-colors.ts` 四处同源）：六合蓝`#5b9dd9`/刑红`#e05c5c`/拱绿`#5cc87f`/冲紫`#a86fd8`/合亮金`#ffd75e`/梅花灰。ASC/DSC/MC/IC 角标玫红 `#d9a8b8`。
- 线条盘布局：**每个星体符号离圆心距离严格相同**（同一半径一圈）；相近度数沿圈贴紧微开，度分朝圆心竖排两行。
- 矢量符号库 `src/lib/astro/glyph-paths.ts`：描边随尺寸等比缩（`strokePx=max(0.95, 1.5*size/24)`——固定 1.5px 缩到 13px 会糊成一团，爸爸点破的设计缺陷）。
- 盘面相位线：**2D 线条盘必须有四色相位弦线+选中高亮；3D 盘（俯视/侧视）一律不画**（相位信息收进行星弹窗/清单/网格）。
- 按钮唯一位：编辑资料/宫位设置/排盘设置 三按钮 = 大屏嵌资料卡下方竖排，小屏才显示顶部控制行（`lg:hidden` 必须是空格隔开的完整字面量——Tailwind v4 扫描器不认粘连在模板串尾的类名，踩过坑）。
- 相位清单行格式（合盘，`SynastryResult.tsx`）：`☽ ⚹ ♅ 58.0° 出2.0°` —— 双方符号夹相位符，**实际夹角紧跟符号（间距≈4px，禁 ml-auto 推远）**，入/出+偏差收尾。
- 相位清单与网格**严格同源**（只列 `aspectMatrixPoints` 十大+四轴）；列表高度硬锁=网格真实高，排满自动开新列。
- 法达盘（`ChartWheel2D.tsx`）：从外到里 = 小运环(61子段)→大运环(9主段)→盘体(整组缩 78%，总外径与普通盘相同)；配色**只保持一种**：已走过=淡灰无色、未走过=主题玫红；符号正立居中不旋转（旋转会斜出环界）；大运年纪放"对着外环同主星小运段"角度（天然错开）、南北交点段不标；**点击段只弹窗不跳转**（弹窗内按钮才跳行运盘定位起日）——防误触丢失法达盘。
- 每颗星/每张牌内容用独立卡片分组；AI 文字后续流入，生成时视口停在牌面/盘面。

**占星术语**（直接用，不需翻译）：本垣/曜升/三分/界/面、宫神星、法达、小限、Aphesis、接纳、互容。
- **接纳=单向、须成相位；互容=双向同住、无需相位**（禁旧词"互溶/慷慨"）。
- 燃烧之路用窄版 ♎14°55′—♏14°55′。
- 占断铁则：牌义/星义是判官，问卦人动机只当"温度计"，不为迎合情绪扭曲占断。

**产品**
- 盘种条顺序：☍合盘 | 天象 本命 行运 三限 次限 月返 日返 法达 日弧 小限；默认落「本命盘」。
- 合盘 16 Tab 顺序：比较盘A 比较盘B 组合盘 马盘A 马盘B 时空盘 组合三限 组合次限 马盘A三限 马盘B三限 马盘A次限 马盘B次限 时空三限 时空次限 本命盘A 本命盘B。
- 比较盘A=内环档案·外环主盘；比较盘B=内环主盘·外环档案。双环含义：内环=本命，外环=推运。
- 动态盘（非本命）不挂本命资料卡，左上放该盘自己的设置卡（盘种标题+时间步进器+跳转+说明+盘面时间+卡下按钮）。
- 时间步进单位：推运类 年/月/日；行运/天象 年/月/日/时/分。
- 档案自动保存：有「盘档案名」才自动存、仅本命盘页触发、重复排同盘不存两条；坏档案（缺 birth/字段非法）在**读取层**过滤丢弃（`src/lib/astro/archives.ts` sanitizeArchive，本地+云端双通道）。

## 4.5 部署流程（完整链路，无独立部署命令）

**触发方式**：`git push origin master` 即部署，全程约 2–4 分钟。

1. 推送到 GitHub `zhanmusijieluo-cloud/tarot-site`（master 分支）。
2. Vercel Git 集成自动触发构建。项目关联信息在仓库根 `.vercel/project.json`（projectId `prj_YmN9Pwryk7iXQB3AHzcd5AKtVCFq`，项目名 tarot-site，账号 `zhanmusijieluo-3684`）；域名 **mustar.vip** 已绑定该项目。控制台入口：vercel.com 登录后 → tarot-site 项目 → Deployments（每次 push 一条构建记录，可看日志）。
3. 构建命令 = `npm run build`（内部先 `node scripts/sync-images.mjs` 同步牌面图再 `next build`）。**sync-images 依赖本地图片目录，构建报图缺先查它**。
4. **环境变量在 Vercel 云端另有一套**（Settings → Environment Variables），不是读 `.env.local`！需要与 `.env.local` 同名同值的：`BAI_API_KEY`、`AGNES_API_KEY`、`AGNES_BASE_URL`、`NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_ANON_KEY`。**⚠️ NEXT_PUBLIC_* 是构建时打进前端代码的——本地 .env.local 改了值（如换 Supabase 项目）而没同步 Vercel 并重新部署，线上就会拿旧值，出现"本地好、线上坏"。任何 .env.local 变更必须手动去 Vercel 同步。** AI 解读慢/失败先查 BAI key 是否还在效。
5. 验证上线（任一）：
   - 简单：浏览器开 mustar.vip **Ctrl+Shift+R** 强刷，看新改动；
   - 工具/脚本：`node scripts/_prod_audit.mjs`（线上 9 页全检）或 curl 线上 API 对数值指纹（此前用此法确认过推运宫头新值）；
   - Vercel Deployments 页状态 = Ready 即成功。
6. 失败处理：Deployments 点进红叉看 Build Log（TS 报错/依赖装挂最常见）→ 本地修复重推。**紧急回滚**：Deployments 列表 → 选最近一次 Ready 的部署 → ⋯ → Rollback（秒级，不用回退 git）。
7. **Supabase 数据库不需要部署**——生产站实时直连云端（anon key 走 `NEXT_PUBLIC_SUPABASE_URL`）。

## 5. 占星算法口径（全部经对拍锁定，改前必读 docs/handoff/参考资料/）

- 排盘封装层 `src/lib/astro/chart.ts`：底层 celestine(MIT)+astronomia；**16 宫制**（placidus/koch/equal/whole/porphyry/regiomontanus/campanus/morinus/vettius/alcabitiuses/sripati/pullen/polich-page/krusinski/carter/vehlow），其中 7 个自算制（`selfHouseCusps`/`cotransEcl`）**逐行复刻 Swiss Ephemeris 官方 swehouse.c**，15 制×3 出生对拍 SE 全 ≤0.004°。Morinus=赤经等分（不是黄道等分）。高纬无解降级波菲里。
- **推运宫头终版口径**（`src/lib/astro/dynamic.ts` recastAxes，已上线）：真盘（时空/马盘A/B）= `新RAMC = 基础盘RAMC + 推进天数×0.9856473°(Naibod平均太阳率)` → 原地点纬度重排 Placidus；次限天数=年龄岁数、三限=岁数×13.368。**零校准常量**（对拍爱星盘：时空三限 ≤0.11°、马盘B三限 ≤0.44°）。组合家族(compS/compT)无真 RAMC，仍用 `PROG_CUSP_CORR`/`PROG_AXIS_CORR` 修正表。
- 三限速率=1天:1 月亮月（引擎取 **27.321582 天** — ⚠️ 该数值实为**分点月 tropical month**；真恒星月是 27.321661，两者差 0.000079 天，对 28 年跨度影响 <0.002°，故**沿用现值不动、勿按"恒星月"改数**）≈每年 13.368 天（不是引擎内置 12 天）。马盘=Marks 原文"本命盘与时空盘的中点"（`davisonBirth(self, davisonIn)`，见 `dynamic.ts:525`）。
- 法达=Abu Ma'shar 制（每大运平分 7 子段、第 1 子段=主星自己、交点不细分、75 年循环）；小限=出生年 1 宫起 101 年；Aphesis=360 天年制（zodiacalReleasing，与宫神星逐日期 100% 吻合，**勿改成 365 天年**）。测试向量在提交 `a00e677`。
- 状态区（`StatusTabs.tsx`）6 Tab 全宫神星风；主星配色单一来源 `src/lib/astro/lord-colors.ts`。
- 详细方法论：`docs/handoff/参考资料/prog-cusp-reverse-engineering.md`（推运宫头反解全程+法达环规格）等 8 份，**动对应模块前必读对应份**。

## 8. 工作方法（怎么改才算"做完"）

1. 改代码 → `npx tsc --noEmit`=0 → `npm run dev` 本地预览 → 跑对应验收脚本（UI 改动用 puppeteer **DOM 断言/像素扫描**，不许只看代码就宣布完成；截图给爸爸或自我核对）。
2. 占星算法改动 → **必须先拿专业工具（测测/爱星盘/宫神星/Astro-Seek）出数对拍**，再动代码（栽过两次大跟头：马盘定义、三限速率）。
3. 回归三件套全绿：astro-chart 12/0、astro-reception 6/0、astro-ui-check 15/15。
4. 提交（信息写清"为什么"）→ `git push origin master` → 提醒爸爸线上生效需几分钟 + **Ctrl+Shift+R 强刷**。
5. **⚠️ 本机铁律：不要用 `git rm`**（2026-09-15 两次踩到）：该环境下 `git rm` 会被中断在「已删工作区文件、未写 index」之间，留下 stale `.git/index.lock`，且工作区文件**批量消失**（`public/` 144 个、`scripts/` 69 个），`git status` 表现为大量**未暂存**删除（而非正常的暂存删除）。
   - **改用**：`rm <明确路径>` + `git add -A <path>`，**每步后立刻用 `git status` 校验条目数**是否与预期一致。
   - **恢复**：确认无 git 进程 → `rm -f .git/index.lock` → `git restore <path>`（两次均完整恢复、零损失）。
6. **长命令也会被中断**：`pip install` / `npm i` 等需 `run_in_background`。联网前先 `unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY`（系统里那个失效代理，见第 6 节）；pip 用清华源、npm 用 `--registry=https://registry.npmmirror.com`。
7. dev 模式下 React 报错条标 "(stale)" 或指向不存在文件 = 热更新残留假警报，先 F5/重开页面再排查（排查过一整轮 100+ 次点击零崩溃的假 bug）。
8. Windows 环境注意：本项目路径含中文；杀僵尸进程用 PowerShell `Stop-Process`（别误杀爸爸自己开的浏览器，只杀 `--headless` 的）。
