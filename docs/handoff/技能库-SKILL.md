## Standard change loop

1. Edit only in the main copy dir.
2. Preview: `npm run dev` → http://localhost:3000. Kill stale dev servers BEFORE verifying: `netstat -ano | grep ':3000.*LISTENING'` → `MSYS_NO_PATHCONV=1 taskkill /PID <pid> /F` (bare `taskkill //PID` fails git-bash argument mangling). A zombie next dev can hold the port while answering nothing — symptom: curl to localhost hangs to timeout AND the fresh `npm run dev` logs 'Port 3000 is in use, using 3001'; kill the squatter instead of debugging code.
3. Verify build: `npm run build` (runs `scripts/sync-images.mjs` first).
4. Commit, then plain `git push origin master`.
5. Verify the push for real: compare `git rev-parse HEAD` (short) against `git ls-remote origin master` and/or `gh api repos/zhanmusijieluo-cloud/tarot-site/commits --jq '.[0].sha'`. Matching fingerprints = success; do not report deployed without this.
6. Deploy is automatic after push (2–3 min).
- When 爸爸 reports '没有变化呀' after a long local stretch, do NOT hunt for a UI bug: (a) count unpushed commits (`git log --oneline origin/master..master | wc -l`), (b) ask/verify which surface he is looking at (localhost vs mustar.vip). Changes intentionally stay local until he says 部署 — report the unpushed count and offer to push instead of debugging phantom regressions. Same triage when he reports a control MISSING entirely (按钮呢 / 看看是不是BUG了 / 不是叫你把X放Y么): headless-count the element on HIS exact URL first — it is nearly always live in the DOM and the finding is a stale page, not a bug; reply with the DOM count + where the control sits (attach a screenshot of the live page), and close every local-only delivery with a Ctrl+F5 reminder so this class stops recurring.

## Hard-won pitfalls

## Reading-room (解读室) streaming design

The interpretation flow lives in `src/app/reading/session/page.tsx` + `src/mcp/server.ts` and is skeleton-first (user's explicit design):

1. Server pushes a skeleton immediately at request time (0 s wait): Part-1 title + card 1 only — anchor comment `<!--card:<id>:<0|1>-->`, `### N. 牌名（正位/逆位）`, position label, DB-sourced 牌性特质. Cards 2..N's skeleton segments are emitted by `feed()` exactly when the AI stream advances to that card. The anchor lets the frontend draw the card image as a component.
   - All card anchors in delta#1 is a bug, not a shortcut: the frontend groups «anchor → next anchor», so every AI field arriving after delta#1 lands in the LAST card's box (one bloated box, empty others). Anchor order must match content order by construction — each card's anchor is emitted milliseconds before its own fields.
2. NEVER embed card images in the skeleton as markdown `![](path)` — markdown imgs cannot get the `rotate(180deg)` reversed cards need. Frontend `MarkdownBlockWithCards` splits anchors and renders `SkeletonCardImage` (rotated when reversed). Markdown imgs in skeletons were tried: broke per-card structure and showed all cards upright.
3. `emittedHeaders` Set stops `feed()` from re-emitting headers/traits the skeleton already sent; removing it duplicates the Part-1 title and traits in the UI. Also never write the Part-1 title inside `cardSkeleton()` itself — it is emitted once by `skeleton()`, and header helpers that bake the title in double it.
6. Group per card on BOTH ends: server sends content strictly inside its anchor block, and frontend `MarkdownBlockWithCards` wraps anchor-through-next-anchor (header + traits + AI fields) in one bordered card container. Plain `---` dividers are too faint — without the container users misread one card's summary as belonging to the pile.
7. During the FIRST generation keep the viewport on the Part-1 spread display (user swipes down to start reading); when generation FINISHES the viewport must NOT move at all — the user may already be mid-scroll reading streamed text, a jump-to-top (or any auto-scroll on completion) breaks them (user explicitly demanded this, commit 8a3b906; the old scroll-back-to-head effect and the resume-follow floating pill are both deleted — do not resurrect either).
4. Send BOTH `reasoning_effort:'low'` and `chat_template_kwargs:{enable_thinking:false}`: qwen's thinking chain tripled latency (11–37 s → 4 s) with no quality gain; the second param covers non-qwen fallback engines.
5. Auto-scroll: follow the streaming tail only while the user hasn't scrolled (wheel/touchmove pauses it permanently for that run — no resume button, removed by user request); on completion, never move the viewport.

## Debugging streaming UI

- Reproduce the delta sequence before touching code: `curl -N http://localhost:3000/api/interpret/stream -H "Content-Type: application/json" --data-binary @req.json` and grep the `"text":"...` events. The channel order tells you which side owns the bug — if the server's deltas are correct (headers placed, dividers right), the defect is in the frontend parser/renderer (`section1Blocks`, `MarkdownBlockWithCards`); do not churn the server.
